Mettere online Flipbook Lab con GitHub Pages

Quattro passaggi, circa 10 minuti, da fare una volta sola. Alla fine l’app sarà all’indirizzo https://niki977.github.io/ultraspeaker-flipbook-lab/ e la potrai aprire da qualsiasi computer con Chrome, Edge o Safari.

!Prima di iniziare

  1. Scarica lo zip ultraspeaker-flipbook-lab.zip e fai doppio clic per estrarlo: ottieni la cartella ultraspeaker-flipbook-lab.
  2. Apri la cartella ultraspeaker-flipbook-lab → vendor → ffmpeg e sposta sulla Scrivania il file ffmpeg-core.wasm (31 MB). Il caricamento dal sito di GitHub rifiuta i file oltre 25 MB: questo file si aggiunge dopo con GitHub Desktop (passaggio «Il motore video»). Senza, l’app funziona ma non crea il MOV trasparente.
  3. Usa Chrome per i passaggi seguenti: è il browser in cui il trascinamento delle cartelle su GitHub funziona meglio.

1Crea il repository

  1. Vai su github.com e accedi con l’account niki977 (lo stesso di QR Lab e Image Lab).
  2. In alto a destra clicca + → New repository.
  3. In Repository name scrivi esattamente ultraspeaker-flipbook-lab.
  4. Scegli Public. Lascia deselezionate le opzioni “Add a README file”, “.gitignore” e “license”.
  5. Clicca Create repository.
Il nome conta: diventa l’ultima parte dell’indirizzo dell’app. Con un altro nome l’app funziona lo stesso, ma l’indirizzo cambia.

2Carica i file

  1. Nella pagina del repository appena creato clicca il link uploading an existing file (nella frase “…or upload an existing file”).
  2. Apri la cartella ultraspeaker-flipbook-lab nel Finder, premi ⌘ + A per selezionare tutto il suo contenuto (file e cartelle) e trascinalo nel riquadro della pagina di GitHub.
  3. Aspetta che l’elenco dei file finisca di caricarsi: devono comparire anche index.html, README.md e le cartelle assets, demo, fonts, js, vendor.
  4. In basso, in Commit changes, clicca il pulsante verde Commit changes.
Importante: trascina il contenuto della cartella, non la cartella ultraspeaker-flipbook-lab stessa. Nella pagina principale del repository index.html deve comparire subito, non dentro un’altra cartella.

3Attiva GitHub Pages

  1. Nel repository clicca Settings (la rotellina, in alto a destra nella barra del repository).
  2. Nel menu a sinistra scegli Pages.
  3. In Build and deployment → Source scegli Deploy from a branch.
  4. In Branch scegli main e cartella / (root), poi Save.
  5. Dopo 1–2 minuti ricarica la pagina: in alto compare “Your site is live at https://niki977.github.io/ultraspeaker-flipbook-lab/”.

4Controlla che funzioni

  1. Apri https://niki977.github.io/ultraspeaker-flipbook-lab/: compare la schermata nera di Flipbook Lab.
  2. Clicca Apri la guida di esempio: si apre il libretto con la copertina “Knowledge is not enough”.
  3. Cambia lingua in alto a destra: il libretto cambia lingua.
  4. Premi Registra, gira una pagina, premi Stop ed esporta un MP4 in 1280 × 720: il file si scarica.
  5. Ripeti scegliendo MOV trasparente: la prima volta compare “Carico il codificatore video…” per qualche secondo (sono circa 30 MB), poi il MOV si scarica. Dalle volte successive è più veloce.
Se l’indirizzo mostra “404”, aspetta ancora un minuto e ricarica. Se resta così, controlla nel repository che index.html sia nella pagina principale e non dentro una cartella.

+Il motore video

Il file ffmpeg-core.wasm (31 MB) è il motore che crea i MOV trasparenti e deve stare nel repository. Il sito di GitHub accetta caricamenti fino a 25 MB, quindi serve GitHub Desktop, l’app gratuita di GitHub per Mac. Si fa una volta sola, circa 10 minuti.

A. Installa GitHub Desktop

  1. Vai su desktop.github.com e clicca Download for macOS.
  2. Apri il file scaricato (nella cartella Download) e trascina GitHub Desktop nella cartella Applicazioni. Aprilo; se il Mac chiede conferma, clicca Apri.
  3. Clicca Sign in to GitHub.com: si apre il browser, accedi come niki977 e clicca Authorize desktop. Il browser ti riporta nell’app.
  4. Nella schermata Configure Git lascia Use my GitHub account name and email address e clicca Finish.

B. Scarica una copia del repository sul Mac

  1. In GitHub Desktop: menu File → Clone Repository… (⇧ ⌘ O).
  2. Nella scheda GitHub.com seleziona niki977/ultraspeaker-flipbook-lab.
  3. Local Path: lascia quello proposto (di solito Documenti/GitHub/ultraspeaker-flipbook-lab) e clicca Clone. In pochi secondi la copia è sul Mac.

C. Aggiungi il motore video

  1. In GitHub Desktop: menu Repository → Show in Finder (⇧ ⌘ F). Si apre la cartella del repository.
  2. Entra in vendor → ffmpeg. Ci sono già ffmpeg.js, 814.ffmpeg.js e ffmpeg-core.js.
  3. Trascina qui dentro ffmpeg-core.wasm (quello messo da parte sulla Scrivania, oppure prendilo di nuovo dallo zip, nella stessa cartella vendor/ffmpeg). Il nome deve restare esattamente ffmpeg-core.wasm.

D. Pubblica

  1. Torna in GitHub Desktop. A sinistra, nella scheda Changes, compare vendor/ffmpeg/ffmpeg-core.wasm con la casella spuntata.
  2. In basso a sinistra, nel campo Summary, scrivi Motore video e clicca Commit to main. Il salvataggio è fatto sul Mac, ma non ancora online.
  3. In alto clicca Push origin: il file viene caricato su GitHub (qualche decina di secondi, 31 MB). Quando il pulsante torna a dire Fetch origin, è finito.

E. Controlla

  1. Su github.com, nel repository, apri vendor/ffmpeg: c’è ffmpeg-core.wasm (31 MB).
  2. Nella scheda Actions l’ultima riga “pages build and deployment” diventa verde dopo 1–2 minuti.
  3. Apri l’app, ricarica con ⌘ + Maiusc + R e crea un MOV: ora il motore arriva dal tuo sito.
Da qui in poi puoi usare GitHub Desktop anche per gli aggiornamenti: copi i file nuovi nella cartella del repository sul Mac (sostituendo quelli vecchi), scrivi un titolo, Commit to main e Push origin. È più comodo del caricamento dal sito e non ha il limite dei 25 MB.
Se qualcosa non va. “Push rejected” o “non-fast-forward”: clicca Fetch origin, poi Pull origin, e ripeti il Push. Il file non compare in Changes: controlla di averlo messo nella cartella clonata (quella aperta con Show in Finder), non nella cartella dello zip. GitHub avvisa solo per file oltre 50 MB: 31 MB va bene, senza strumenti aggiuntivi.

5Il pulsante in PowerPoint

Il componente aggiuntivo mette il pulsante Flipbook Lab nella scheda Home di PowerPoint, nel gruppo The Ultraspeaker. Il pulsante apre un pannello da cui il Flipbook Lab si apre nel browser: PowerPoint per Mac non permette ai componenti aggiuntivi di salvare file, nel browser invece il video si salva in Download oppure, con Salva in…, nella cartella che scegli.

  1. Controlla che su GitHub ci siano addin.html e ultraspeaker-flipbook-lab-manifest.xml.
  2. Chiudi PowerPoint (⌘ + Q).
  3. Nel Finder premi ⌘ + Maiusc + G e incolla:
    ~/Library/Containers/com.microsoft.Powerpoint/Data/Documents/wef
    Se la cartella wef non c'è, apri Documents e creala con quel nome esatto.
  4. Copia dentro ultraspeaker-flipbook-lab-manifest.xml, accanto ai manifest degli altri Lab. Se il Finder chiede di sostituire un file, rispondi No e controlla il nome.
  5. Riapri PowerPoint e una presentazione. Il pulsante Flipbook Lab è nella scheda Home. Se non compare: Inserisci → Componenti aggiuntivi → I miei componenti aggiuntivi, sezione Componenti aggiuntivi per sviluppatori, e scegli The Ultraspeaker Flipbook Lab.
Il manifest va copiato una volta sola. Gli aggiornamenti del sito arrivano da soli; solo se cambia il manifest va ricopiato nella cartella wef.

?Buono a sapersi

  1. Aggiornare l’app: quando ti mando una nuova versione, nel repository clicca Add file → Upload files, trascina i file nuovi (stessi nomi) e fai Commit changes. GitHub sostituisce quelli vecchi; dopo un minuto l’app è aggiornata (se non vedi le modifiche, ricarica con ⌘ + Maiusc + R).
  2. Privacy: il repository è pubblico, quindi chiunque può vedere il codice e usare l’app. I PDF che apri però non vengono mai caricati: restano sul computer di chi usa l’app.
  3. Browser: Chrome ed Edge sono i più veloci per creare i video. Safari va bene per sfogliare, sottolineare e fare gli MP4.
  4. Il tuo dominio: in futuro l’app può stare anche su theultraspeaker.com (per esempio theultraspeaker.com/flipbook) copiando la stessa cartella sul sito.
  5. Licenze: pdf.js (Apache 2.0), mp4-muxer (MIT), ffmpeg.wasm (MIT, motore FFmpeg GPL); i dettagli sono nella cartella vendor.
